# api/data/ and pipelines/

## `api/data/`

`data.go` embeds what the server reads.

- `rotation.json`: the schedule (update `checked`/`checked_by` when you change it).
- `colonias.json`: generated by `pipelines/siapa_colonias.py` from SIAPA's 12 Oct PDF (see README; SIAPA's 13 Oct reissue truncates columns: don't regenerate from it).
- `colonias_siapa.topo.json`: the copy of SIAPA's map the API looks zones up in (`pipelines/siapa_mapa.py` writes it with the web copy).
- `colonias_mapa.json`: the colonias of SIAPA's map, once per name, municipio and postal code, with their zones by share of area, the main one first (`pipelines/mapa_colonias.py`).
- `otras_colonias.json`: names from INE (`pipelines/colonias_poligonos.py`), with zones from SIAPA's map through `mapa_colonias.py`.
- `zonas.geojson`: the old My Maps KML's zones (`pipelines/siapa_zonas.py`), which SIAPA no longer shows. Only `colonias_poligonos.py`, `mymaps_kml.py` and `zonas_preview.py` read it.

## `pipelines/` (Python, standard library unless noted)

- `siapa_watch.py`: fetches SIAPA's `index.html`, `colonias_siapa.pdf`, its map (`/geo/rotacion-siapa.topo.json`) and `api/ajustes.php` (the cut days and hand-made colonia zone changes SIAPA edits from its admin panel; `index.html` doesn't change when they do), and compares their SHA-256 with the baseline in `siapa_sources.json`, the map with `web/colonias_siapa.topo.json`, and the days with `rotation.json`; a difference counts as a change until the repo matches. `.github/workflows/siapa-watch.yml` runs it hourly (GitHub starts scheduled runs hours late) and opens or comments on the issue «SIAPA cambió sus fuentes» once per state of SIAPA's files and of the repo's match with them; its last step enables both scheduled workflows again through the API, since GitHub disables a public repo's schedules after 60 days without activity. CI never commits the baseline: after reviewing a change, run `python3 pipelines/siapa_watch.py --update` and commit `siapa_sources.json`. SIAPA's CloudFront caches each file up to a day; query strings and no-cache headers don't bypass it.
- `siapa_mapa.py` writes `web/colonias_siapa.topo.json` and its `api/data` copy from the TopoJSON and `ajustes.php` behind SIAPA's map, with `l` on the colonias whose zones SIAPA's PDF list gives differently; it warns when `ajustes.php`'s days differ from `rotation.json` and doesn't apply its hand-made colonia changes yet (none so far). Then `mapa_colonias.py` writes `colonias_mapa.json` and the zones of `otras_colonias.json`. SIAPA's map gives no zone to 1,579 colonias and puts zones 1 and 7 on only 15 and 11 colonias, so zone shares there rest on few colonias.
- When the rotation changes: update `rotation.json`, run `cmd/calendars` from `api/`, then `zonas_json.py` and `simple_page.py`; `scripts/check.sh` fails until all are in sync. Nothing checks hand-written copies: grep `web/`, `.claude/rules/` and the local research folder (fichas, transparency notes) for each changed zone's old days and for claims about how many days a zone loses («de 2 a 3 racionamientos»), and rebuild any handout.
- `colonia_pages.py` writes `web/colonia/<slug>.json|.html` and `index.html` (A–Z) from `colonias_mapa.json`, the map's area shares and `rotation.json`: weekdays and checked date only, never next dates; slug = name-municipio (ASCII, `-`), plus `-<cp>` when name and municipio repeat; the build fails on a collision. Rerun it with `zonas_json.py` when the rotation or the map changes.
- `colonias_poligonos.py` writes `pipelines/colonias.geojson` (INE outlines of SIAPA's colonias; no page loads it) and the names of `otras_colonias.json`.
- `promesas.py` and `publicaciones.py` build and check /promesas and `web/publicaciones.json` (rules in `.claude/rules/evidence.md`). `zonas_json.py` builds the static schedule fallback `web/zones.json`; `simple_page.py` builds the low-data `/simple` from the shared rotation and publications. CI checks these and `mapa_colonias.py`.
- `secciones_ine.csv`: INE electoral section → Jalisco local district (4,080 sections; shared by Tachis Villalba, credited on /exige; identical to INE's catalogue for entidad 14 on cartografia.ine.mx, cutoff 19 Jan 2026, checked 15 Oct 2026). `secciones_escribe.py` rewrites the `SECCIONES` string in `web/exige.html` from it.
- `siapa_colonias.py` (needs pdfplumber, see README), `siapa_zonas.py`, `zonas_preview.py` (draws `experiments/landing/zonas.svg`) and `mymaps_kml.py` serve the older sources.
- `cisternas.py` writes `web/cisternas.json` (in `check.sh`'s `--check` loop) from the hand-curated `cisternas_fuente.json`: exact points only where an official map gives coordinates (Tlaquepaque's public Google My Map, layers MUNICIPAL 1 and SIAPA, address and coordinates only, never its «PERSONA GOB» field or its PROPUESTAS layer), and a colonia (outline and centre from `colonias_siapa.topo.json`) where a source names only the colonia (Guadalajara's nine, Tonalá's first five). Places a source names without a mappable spot go in `sin_coordenadas`/`sin_ubicar`. Field list for pinning the rough ones: `~/agua-gdl-notes/projects/cisternas-campo.md`. Sources checked 3 Nov 2026.
- **A new check counts what it covered.** It prints how many real items it examined and fails at zero, and it's tested by changing a real row or file in its real shape before anyone writes that something is enforced (6 Nov: three new checks passed while matching nothing).
