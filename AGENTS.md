# AGENTS.md

Instructions for AI coding agents working in this repo. Humans: see README.md (Spanish).

## What this is

Agua GDL sends free WhatsApp and Telegram reminders the evening before each cut of SIAPA's water rotation in Guadalajara (Oct 2026 – Mar 2027), and collects "how did the water come back" reports. It's a civic project: no official affiliation, nonpartisan.

## Layout

- `api/`: Go module `aguagdl/api` (Go 1.27, pgx v5). Entry points `cmd/server` (API, webhook, nightly reminders, daily purge) and `cmd/notify` (sends `cambio_rotacion` to one zone, or with `-tomorrow` tomorrow's reminder as a normal text to the zone's subscribers inside WhatsApp's 24-hour window, reserved in `reminder` so the nightly run won't repeat it, or with `-avisos`, once, the message telling Telegram subscribers about the notice two days before; dry run unless `-send`; run by the maintainer, see README).
  - `internal/rotation`: schedule math and Spanish date formatting. Times are always `America/Mexico_City` (UTC−6, no DST); binaries embed `time/tzdata`.
  - `internal/geo`: zone lookup by point (SIAPA polygons).
  - `internal/colonias`: name normalization and fuzzy search.
  - `internal/wa`: WhatsApp Cloud API client, webhook types, signature check.
  - `internal/tg`: Telegram Bot API client, update types, webhook secret check. The token is in every request URL, so errors never include the URL.
  - `internal/bot`: inbound message routing for both channels: `Handle` (WhatsApp) and `HandleTelegram` feed the same handlers, which reply with channel-neutral `Reply` values rendered per channel. **All user-facing Spanish copy lives in `internal/bot/messages.go`** (WhatsApp-style `*bold*`; Telegram gets it as HTML). Replies are stored in `pending_reply` (with their recipient) in the same transaction as the command and its deduplication marker, then each is claimed in its own commit, sent and deleted: a refused reply (e.g. Telegram's 429) is released and the webhook's redelivery sends it without replaying the command; one that may have been delivered (timeout, 5xx, a crash or database error after the send) stays claimed and is never resent. `Unsubscribe` deletes the replies queued for that person, so an earlier confirmation can't follow the goodbye. Unsent replies hold the chat ID and text, so the daily purge deletes them after a day.
  - `cmd/calendars`: writes `web/calendario/zona-N.ics` (subscribable calendars linked from /mizona) from `rotation.json`; run it from `api/` whenever the rotation changes. `internal/calendar`'s test fails if the published files are stale.
  - `cmd/tgsetup`: one-off; sets the Telegram webhook (with `TG_WEBHOOK_SECRET`), name, descriptions and command menu.
  - `internal/reminders`: the nightly 20:00 sender, caps and heartbeat. It works by blocks of cuts: cut days at most `rotation.BlockGap` (2) days apart, since neighbours report the water goes a day early and takes days to come back (zone 1's Wed–Fri–Sun is one block; so are zone 5's Tue–Wed and zone 7's weekend). Each evening a subscriber gets at most one of: on Telegram, a notice two days before a block (notice key `previo:<first day>`); the reminder the evening before it, skipped for whoever answered «No»; on Telegram, the evening after a block, «¿Ya regresó?» with REPORTAR's answers to whoever answered «No» or «Poca» and hasn't reported since (`regreso:<first day>`), but not on a night their zone gets a notice. Notices and reminders ask «¿Ahorita tienes agua?» with three buttons (`A:zone:date:answer`); answers go to `water_report`, one per subscription and block, only from a subscription that was sent that block's notice or reminder, and «No» gets the pipa contacts. The calendars' alarms follow the same blocks. Unlike WhatsApp's approved template, the Telegram texts attribute SIAPA's «solo baja la presión, por un día» instead of stating it.
  - `internal/notices`: one-off templates to a zone (`cambio_rotacion`), reserved in the `notice` table with the same guarantees as reminders.
  - `internal/webreports`: the reports people make on /reportes (no account): one colonia (`name|municipio|cp`, as listed in `api/data/colonias_mapa.json`), an answer (sin_agua, baja, con_agua) and optional turbia/olor/sedimento. They live in memory for the map (`GET /v1/reportes` builds the last 24 hours, the all-time count and the bot's answers by zone from memory, cached 30 s) and reach Postgres (`web_report`) in batches every 15 minutes and at shutdown, so map traffic doesn't keep Neon awake; the bot's answers are re-read at most every 30 minutes and only while someone is looking. `POST /v1/reportes` accepts only the site's origin (and localhost) and limits each client address (IPv6 /64) to 3 reports per colonia and 20 in all per hour, held in memory only and never stored, and everyone together to 5,000 an hour (503), which bounds memory and the database however many addresses send.
  - `internal/store`: Postgres, with embedded SQL migrations in `internal/store/migrations` (add new numbered files; never edit applied ones). `Migrate` holds a Postgres advisory lock so two machines starting at once don't race; that needs a direct connection, so `DATABASE_URL` must be Neon's non-pooler URL.
  - `internal/fake`: in-memory test doubles.
- `api/data/`: embedded data. `rotation.json` is the schedule (update `checked`/`checked_by` when you change it); `colonias.json` is generated by `pipelines/siapa_colonias.py`; `zonas.geojson` is generated from SIAPA's public My Maps KML by `pipelines/siapa_zonas.py` (byte-identical output; it fails unless the KML has exactly zones 1–7).
- `pipelines/siapa_watch.py` (standard library only): fetches SIAPA's `index.html`, `calendario.webp`, `colonias_siapa.pdf` and zone KML, compares their SHA-256 with the baseline in `pipelines/siapa_sources.json`, and checks the converted KML against `zonas.geojson`. `.github/workflows/siapa-watch.yml` runs it every 6 h and opens (or comments on) the issue "SIAPA cambió sus fuentes"; CI never commits the baseline. After reviewing a change, run `python3 pipelines/siapa_watch.py --update` and commit `siapa_sources.json`. SIAPA's CloudFront caches each file up to a day; query strings and no-cache headers don't bypass it. The baseline PDF is SIAPA's 13 Oct reissue with truncated columns: don't regenerate `colonias.json` from it.
- `pipelines/mapa_colonias.py` writes `api/data/colonias_mapa.json` (the colonias of `web/colonias_siapa.topo.json`, once per name, municipio and postal code) after `siapa_mapa.py`; `internal/webreports`'s test fails if it is stale.
- `pipelines/secciones_ine.csv`: INE electoral section → Jalisco local district (4,080 sections; shared by Tachis Villalba (credited on /escribe), identical to INE's "Catálogo de Secciones con Distritos Electorales Locales" for entidad 14, cutoff 19 Jan 2026, on cartografia.ine.mx, checked 15 Oct 2026). `python3 pipelines/secciones_escribe.py` rewrites the `SECCIONES` string in `web/escribe.html` from it.
- `web/`: the static site for aguagdl.com, plain HTML with no build step. `index.html` is the landing page (colonia search, the live week of zones, the map, the Telegram reminder, one Congreso ask, links to the other pages, «Por qué», contact); every page loads `/theme.js` in its `<head>` (the light/dark button in the header; light is the default and the page's `prefers-color-scheme: dark` rules apply only after a visitor picks dark, so style dark mode only with those media queries and use `aguaDark()` instead of `matchMedia` in scripts); pages reference the icon sprite as `/icons.svg?v=N#name` and browsers cache it for a day, so bump `v` in every page when you change `icons.svg`; keep its `facebook-domain-verification` meta tag, which keeps aguagdl.com verified in Meta; `logo.svg` is a transparent cut of `aguagdl.svg`; the favicon files are copies of `aguagdl_favicon/`. Cloudflare Pages deploys it to https://aguagdl.com on every push to `main` (no build command, output directory `web`). Unknown paths return an empty 404 (checked 14 Oct; Pages does not fall back to `index.html` here); `/privacidad` is served from `privacidad.html`. `www.aguagdl.com` 301-redirects to the apex through a Cloudflare Redirect Rule (proxied AAAA `www` → `100::`), not through Pages, so don't add `www` as a Pages custom domain. `privacidad.html` and `terminos.html` are the privacy notice and terms of use, live since 14 Oct 2026 (Meta's app settings link to them, so keep their URLs); `avisos.html` is the subscribe page for both channels (WhatsApp `wa.me` and Telegram `t.me/AvisoAguaGDLbot`); `mizona.html` offers both per zone (`ZONA N` prefilled on WhatsApp, `/start zN` on Telegram). `mizona.html` ("¿Qué zona me toca?") looks up the zone by location or colonia (the colonia box suggests the API's matches while typing, like /mapa; a pick runs the same flow as a search), and on tap shows the same SIAPA map as /mapa through `web/mapa.js` (Leaflet self-hosted in `web/vendor/leaflet-1.9.4/`, OSM tiles, allowed in `_headers` and named in the privacy notice): every colonia filled by its zone, the listed colonias outlined and labelled, a tap on any colonia gives its zone with the same border/split wording, and a tap on a spot with no colonia still asks `/v1/zone`. `web/zonas.geojson` (a copy of `api/data/zonas.geojson`; `internal/geo`'s test fails if they differ) and `web/colonias.geojson` (INE outlines from `pipelines/colonias_poligonos.py`, exact name matches plus a checked alias table) are no longer loaded by any page; they stay for the list-vs-map checks behind «Ten en cuenta»; `mapa.html` (/mapa, where the landing's «Ver mapa detallado» button goes) shows the whole map at once, like SIAPA's own map since 16 Oct 2026: every colonia of the metropolitan area filled by zone, tap one or search by name, municipio or postal code for a card with its zone, days and next cut; its data is `web/colonias_siapa.topo.json`, built by `pipelines/siapa_mapa.py` from the TopoJSON and `ajustes.php` behind SIAPA's map (the page decodes TopoJSON itself, no library), with `l` on the colonias whose zones SIAPA's PDF list gives differently; the days come from `/v1/zones`, never from that file, and the script warns when SIAPA's `ajustes` days differ from `rotation.json`. `web/mapa.js` holds the code both pages share: TopoJSON decoding, zone colours, drawing and highlights, and the wording helpers `zones`, `label` and `describe`; `p` in the data is each multi-zone colonia's share of area per zone (sampled on a grid), and below `BORDER` (15 %) the pages say the colonia is in one zone «al límite con» the other instead of in both, since most of SIAPA's two-zone colonias only graze a border. `reportes.html` («¿Hay agua en tu colonia?», /reportes; linked from the landing and /mapa) is the neighbours' map: SIAPA's colonias coloured by the majority of the last 24 hours' reports, rings with the count (from zoom 13, or always with 60 colonias or fewer), a card per colonia with its counts and the report form, the day's summary, the bot's answers by zone (detail only from `MIN_REPORTS_SHOWN`), search, location in the browser and `?q=&m=&cp=` links; a browser keeps its own report of a colonia for an hour in `localStorage` so the card thanks instead of asking again. `resultados.html` (which showed `/v1/results`) was removed on 16 Oct 2026 until there are enough reports (restore it from git history, with its menu and footer links). `mizona.html` calls `https://api.aguagdl.com`, and `?api=http://localhost:PORT` points it at a local API (only localhost is accepted). `_headers` sets the security headers Cloudflare Pages sends with every page (HSTS, nosniff, referrer and permissions policies, no framing) and a CSP that also allows Cloudflare Web Analytics' beacon (`static.cloudflareinsights.com`; it is enabled from the Pages project's Metrics tab, Cloudflare injects the script, and point 7 of the privacy notice describes it); `/mizona` needs `geolocation=(self)`; `_redirects` sends the old /llego there with a 301. The landing is the former variant v5 (colonia search plus the live week of zones from `/v1/zones`); `/v5` 301s to `/`. The other variants and the previous landing (`index-before-v5.html`) are kept, unpublished, in `experiments/landing/` (only `web/` is deployed).
- Advocacy pages: `escribe.html` (write to the 38 deputies; tabs; «Por qué»), `contamina.html` (Río Santiago polluters, sourced) and `antisionismo.html` (served at /antisionismo; `_redirects` sends the old /palestina there with a 301; the maintainer's position against the State of Israel). Every factual claim there links its source; keep it that way, and never state that an Israeli company is part of the Jalisco aqueduct APP unless a source shows it.
- `promesas.html` (/promesas, «Lo que prometieron del acueducto y lo que dicen los documentos»; the menu's «Cuentas» entry, on every page after «Congreso»): each government water promise beside the law or document, with a verdict and steps. Its cards and meter are generated: edit `web/promesas.json`, then run `python3 pipelines/promesas.py` (standard library). It fails unless every source has an archive.org snapshot or a private copy (`"captura": "privada"`), «Incumplida» has two independent sources, «Se contradice» quotes the document, each entry has one core step, no «miente/engañó» appears outside quotes, and «israelí» appears only in a quote; `--check` fails if the page is stale; `--drafts --out DIR` previews without archives outside `web/`. The plan, research and private copies are in the private notes repo (`projects/promesometro.md`). On phones the menu's seven entries sit in two rows (4 + 3), and below 980 px the icons hide.
- Brand assets at the repo root: the logo is a blue water drop (`#017CDC`, shadow `#015198`) with "GDL" in white.
  - `aguagdl.svg`: traced vector, 6 KB; use it for anything drawn in a page. The original 1254×1254 raster (`aguagdl.png`, about 1 MB) was removed from the repo on 16 Oct 2026; it's in git history and in `~/agua-gdl-notes/`, and `aguagdl_favicon/android-chrome-512x512.png` serves for profile photos.
  - `aguagdl_favicon/`: `favicon.ico` (16, 32), 16/32 px PNGs, `apple-touch-icon.png` (180), `android-chrome-*` (192, 512) and `site.webmanifest`. The manifest uses root paths, so copy the folder's files to the site root when `web/` is built.

## Commands

```sh
cd api
go vet ./... && go test ./...          # unit tests (integration tests skip)
docker run -d --rm --name aguagdl-pg -e POSTGRES_PASSWORD=dev -e POSTGRES_DB=aguagdl -p 55432:5432 postgres:17-alpine
TEST_DATABASE_URL=postgres://postgres:dev@localhost:55432/aguagdl?sslmode=disable go test -race ./...   # with integration tests
```

CI (`.github/workflows/ci.yml`) runs vet and race tests against Postgres 17 and builds `infra/Dockerfile`. Run the tests and check the result yourself before pushing.

## Rules

- Never send real WhatsApp or Telegram messages from tests or local runs. `REMINDERS_ENABLED` and `TG_REMINDERS_ENABLED` stay false unless the maintainer turns them on in production.
- Channels: `subscriber.channel` is `wa` or `tg` (one subscription per channel and user ID); `reminder` and `notice` rows carry the channel too. Meta's caps and `NightCap` count WhatsApp only. The runner sends each enabled channel independently. A Telegram 403 (bot blocked) deletes the subscription and marks the attempt `blocked`; a 429 is waited out (nothing was sent).
- Don't relax the safety rails: idempotent sends per (subscriber, cut date), daily and monthly caps, the heartbeat, never resending an attempt WhatsApp may have accepted (only `rejected` attempts are retried), and the webhook signature check. A duplicate or missed reminder is the worst bug here.
- Caps: `DAILY_CAP` counts distinct recipients in a moving 24 hours, like Meta's messaging limit (250 for a new portfolio), across reminders and notices; when it's full the runner waits for the window instead of skipping anyone, and gives up only at `CATCH_UP_UNTIL_HOUR`. The bot refuses a subscription or zone change that would push any night over `DAILY_CAP` (`msgFull`). Raise `DAILY_CAP` only after Meta raises the portfolio's limit. `MONTHLY_CAP` counts messages (cost). Every WhatsApp reservation (nightly run, `notify`, `-tomorrow`) re-checks both caps under one Postgres advisory lock (`store.Budget`), so concurrent senders can't overshoot them; the admission check holds its own lock (`ZoneCounts`) through the subscription. Reports: only a subscription that already existed when a cut began can report that cut, so BAJA and subscribing again can't add reports. After `rotation.Expired` the bot refuses new subscriptions and zone changes (BAJA still works).
- Privacy: store only the phone number, zone and consent time. BAJA must delete the subscriber; reports stay anonymous. Reports from /reportes never carry an IP, a location or a subscriber. A phone number belongs to at most one subscription, the one Meta most recently tied to it (partial unique index, migration 005): `Subscribe` and `ChangeUser` drop any other row holding it, and BAJA deletes every row with the sender's ID or number. Thirty days after `end` in `rotation.json` the server deletes every subscriber (`rotation.Expired`), as the privacy notice promises: move `end` if SIAPA extends the rotation. Never log phone numbers or WhatsApp message IDs: a wamid embeds the phone number, so the database stores only its SHA-256. No secrets in the repo; config comes from env vars (see `.env.example`).
- Public API protections: `/v1/*` allows 120 requests per minute per client IP (`Fly-Client-IP`, set by Fly's proxy; api.aguagdl.com is DNS-only, not behind Cloudflare's proxy) and, past 10,000 addresses in a minute, 1,200 shared among the new ones; `/v1/results` reuses one query for 5 minutes so web traffic can't keep Neon awake and burn its free compute hours; and `/v1/zone` is `no-store` because it carries coordinates. `/v1/reportes` serves from memory, and its POST has its own per-address limits and an origin check (see `internal/webreports`). Keep them when you add endpoints.
- WhatsApp templates are approved by Meta. If you change the parameters or buttons the code sends, the template in WhatsApp Manager must change too.
- Keep code comments sparse and match the surrounding style. Commit messages in English. User-facing copy in plain Mexican Spanish.
- Don't force-push. The maintainer may be editing in parallel: check `git status` before you edit or commit.
