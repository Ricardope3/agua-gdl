# AGENTS.md

Instructions for AI coding agents working in this repo. Humans: see README.md (Spanish).

This file says how things are now. History lives in git: when something changes, update the fact here instead of adding a dated entry, and leave out what the code already says plainly.

## What this is

Agua GDL sends free Telegram reminders before each block of cuts of SIAPA's water rotation in Guadalajara (Oct 2026 – Mar 2027): a notice two days before and a reminder the evening before. It also runs the neighbours' report map (/reportes), collects "how did the water come back" answers and publishes advocacy pages (/exige, /promesas, /escribe…). WhatsApp ran until 15 Oct 2026, when Meta closed the account; its code stays, off without `WA_TOKEN`. It's a civic project: no official affiliation, nonpartisan.

## Layout

### `api/`: Go module `aguagdl/api` (Go 1.27, pgx v5)

- `cmd/server`: the API, the webhooks, the nightly reminders and the daily purge.
- `cmd/notify` (run by the maintainer, see README): sends `cambio_rotacion` to one zone; `-tomorrow` sends tomorrow's reminder as a plain WhatsApp text inside the 24-hour window, reserved in `reminder` so the nightly run won't repeat it; `-avisos` sends the one-off message about the notice two days before (never sent). Dry run unless `-send`; a dry run doesn't migrate the database.
- `cmd/calendars`: writes `web/calendario/zona-N.ics` (subscribable calendars linked from /mizona) from `rotation.json`. Run it from `api/` whenever the rotation changes; `internal/calendar`'s test fails if the published files are stale.
- `cmd/tgsetup`: one-off; sets the Telegram webhook (with `TG_WEBHOOK_SECRET`), name, descriptions (at most 120 and 512 characters) and command menu. Re-run it after changing them. It keeps the updates Telegram holds for the webhook unless `-drop-pending`.
- `cmd/informe` (with `internal/informe`): off until there are enough reports. It wrote the Monday count of last week's map reports and bot answers (`web/semana/`) and printed the email for SIAPA, the CEA, the municipios, the Congreso and the CEDHJ. Its page `web/informes.html` and every mention of a Monday count were removed; restore them from git history (`cf999bf`) before running it.
- `internal/rotation`: schedule math and Spanish date formatting. Times are always `America/Mexico_City` (UTC−6, no DST); binaries embed `time/tzdata`. A block of cuts is cut days at most `BlockGap` (2) days apart, since neighbours report the water goes a day early and takes days to come back (zone 1's Wed–Fri–Sun is one block; so are zone 5's Tue–Wed and zone 7's weekend). `Over` is true from the day after `end`, `Expired` from thirty days after it.
- `internal/geo`: zone lookup by point on SIAPA's map (`api/data/colonias_siapa.topo.json`, a copy of `web/colonias_siapa.topo.json`; the test fails if they differ). Inside a colonia outline, the zones SIAPA's map gives that colonia (only the side of a split colonia the point is on; none when the map leaves it out), else SIAPA's zone polygons. SIAPA sets colonias' zones by hand, so many lie outside its zone polygons (VALLARTA NORTE, zone 6).
- `internal/colonias`: name normalization and fuzzy search. `internal/wa`: WhatsApp Cloud API client, webhook types, signature check.
- `internal/tg`: Telegram Bot API client, update types, webhook secret check. The token is in every request URL, so errors never include the URL. A request that never got a connection (DNS, dial, TLS) fails with `NotSentError`, which counts as refused: the runner waits and retries it, and the run retries it later; anything after the connection stays uncertain.
- `internal/bot`: inbound routing for both channels. `Handle` (WhatsApp) and `HandleTelegram` feed the same handlers, which reply with channel-neutral `Reply` values rendered per channel.
  - **All user-facing Spanish copy lives in `internal/bot/messages.go`** (WhatsApp-style `*bold*`; Telegram gets HTML). What the user typed is echoed without `*` and `_`, since Telegram refuses a message whose tags don't nest.
  - Replies go to `pending_reply` (with their recipient) in the same transaction as the command and its deduplication marker; one statement then claims them, commits, and each is sent and deleted. A refused reply (Telegram's 429, or a connection cut by the webhook's deadline) is released with those not yet sent, and the webhook's redelivery sends it without replaying the command; one that may have been delivered (timeout, 5xx), or was claimed when the process died, is never resent. `Unsubscribe` deletes the person's queued replies, so a confirmation can't follow the goodbye. The daily purge deletes unsent replies, which hold the chat ID and text, after a day (the privacy notice says so).
  - Typed answers (sí, no, ya no, poca, baja presión…) get a pointer to the buttons, to the location (the bot is stateless, so a «no» may answer «¿Es la tuya?») and to BAJA. «Ya no» is not a stop word, and the report button reads «Poca presión» so a typed «baja» isn't confused with it.
  - Buttons that name a zone (`A:zone:…`, `R:zone:…`) end in an 8-character HMAC of chat, kind, zone and date (`SignButtons`, keyed from `TG_WEBHOOK_SECRET`): the bot believes the zone only if it's the subscriber's own or the signature checks out, so made-up callback data can't answer for another zone, while a report still counts for the zone it was asked about after a zone change. Callback data fits Telegram's 64 bytes; a test checks every colonia in `colonias.json`, the only list offered as buttons.
  - The confirmation lists the rest of a block under way (no message comes for those cuts), and the confirmation and the greeting name the next message the nightly run will send, leaving out the reminder it skips for whoever answered «No». Once the rotation is over, a subscriber's greeting offers only BAJA.
  - It subscribes only to zones the schedule has days for: a spot or a colonia without one gets `msgOutside` or `msgColoniaOutside`.
- `internal/reminders`: the nightly 20:00 sender, caps and heartbeat. Each evening a subscriber gets at most one of: on Telegram, a notice two days before a block (notice key `previo:<first day>`); the reminder the evening before it, skipped for whoever answered «No»; on Telegram, the evening after a block, «¿Ya regresó?» with REPORTAR's answers to whoever answered «No» or «Poca» and hasn't reported since (`regreso:<first day>`), but not on a night their zone gets a notice.
  - Notices and reminders ask «¿Ahorita tienes agua?» with three buttons (`A:zone:date:answer`); answers go to `water_report`, one per subscription and block, only from a subscription that was sent that block's notice or reminder, and «No» gets the pipa contacts (`msgPipa`: SIAPATEL and /pipas).
  - The welcome (headed «El agua es un derecho. Exígelo.»), the help and the confirmation lead with the reports map, /exige and PIPA; the reply to «No» and «Poca» links the map and /exige; the reminders come second. Unlike WhatsApp's approved template, the Telegram texts quote SIAPA («por máximo un día», «no serán cortes totales») instead of stating it as fact.
  - The notice, like the reminder, skips whoever subscribed after the run hour, so BAJA and subscribing again can't repeat it when a run retries. The calendars' alarms follow the same blocks.
- `internal/notices`: one-off templates to a zone (`cambio_rotacion`), reserved in the `notice` table with the same guarantees as reminders.
- `internal/webreports`: the reports people make on /reportes (no account): a colonia (`name|municipio|cp`, from `api/data/colonias_mapa.json`), an answer (sin_agua, baja, con_agua) and optional turbia/olor/sedimento.
  - They're held in memory and written to Postgres (`web_report`) every 15 minutes and at shutdown, so map traffic doesn't wake Neon. `GET /v1/reportes` builds from memory the last 24 hours, the all-time count, the bot's answers by zone and the week, cached 30 s and encoded once (plain and gzipped); the bot's answers are re-read at most every 30 minutes, only while someone is looking.
  - `POST /v1/reportes` accepts only the site's origin (and localhost; any script can claim it, so the limits do the work). The hourly limits per IPv6 /64, /56 and /48 and per IPv4 address (looser, since carriers and home providers share one among many customers) are the constants at the top of `webreports.go`. A colonia takes reports from at most 30 networks an hour (an IPv4 address or an IPv6 /48 counts once and puts at most 10 into it), so no single network can fill it and lock its neighbours out; everyone together gets 5,000 an hour. Addresses and networks live in memory only, so a restart clears them; they're forgotten after about an hour and never stored (the privacy notice says so). Cloudflare Turnstile would stop scripts, but needs keys, the CSP and the privacy notice.
  - The week (`semana`) puts the last 7 days of map reports (in their colonia's main zone) and bot answers (`water_report`, `cut_report`) beside SIAPA's cut days (`Board.Cuts`). Any split of answers shows only from `MIN_REPORTS_SHOWN`, and never where subtracting a public count (the map's are public by colonia) would give a few answers away; the comments in `webreports.go` say how.
- `internal/store`: Postgres, with embedded SQL migrations in `internal/store/migrations` (add new numbered files; never edit applied ones). `Migrate` holds a Postgres advisory lock so two machines starting at once don't race; that needs a direct connection, so `DATABASE_URL` must be Neon's non-pooler URL.
- `internal/fake`: in-memory test doubles. Keep them behaving like the real store and clients: `SaveReport` keeps one report per subscription and cut, and `Telegram.Send` refuses, as Telegram does, HTML whose tags don't nest and callback data over 64 bytes.

### `api/data/`

`data.go` embeds what the server reads.

- `rotation.json`: the schedule (update `checked`/`checked_by` when you change it).
- `colonias.json`: generated by `pipelines/siapa_colonias.py` from SIAPA's 12 Oct PDF (see README; SIAPA's 13 Oct reissue truncates columns: don't regenerate from it).
- `colonias_siapa.topo.json`: the copy of SIAPA's map the API looks zones up in (`pipelines/siapa_mapa.py` writes it with the web copy).
- `colonias_mapa.json`: the colonias of SIAPA's map, once per name, municipio and postal code, with their zones by share of area, the main one first (`pipelines/mapa_colonias.py`).
- `otras_colonias.json`: names from INE (`pipelines/colonias_poligonos.py`), with zones from SIAPA's map through `mapa_colonias.py`.
- `zonas.geojson`: the old My Maps KML's zones (`pipelines/siapa_zonas.py`), which SIAPA no longer shows. Only `colonias_poligonos.py` and `zonas_preview.py` read it.

### `pipelines/` (Python, standard library unless noted)

- `siapa_watch.py`: fetches SIAPA's `index.html`, `colonias_siapa.pdf`, its map (`/geo/rotacion-siapa.topo.json`) and `api/ajustes.php` (the cut days and hand-made colonia zone changes SIAPA edits from its admin panel; `index.html` doesn't change when they do), and compares their SHA-256 with the baseline in `siapa_sources.json`, the map with `web/colonias_siapa.topo.json`, and the days with `rotation.json`; a difference counts as a change until the repo matches. `.github/workflows/siapa-watch.yml` runs it hourly (GitHub starts scheduled runs hours late) and opens or comments on the issue «SIAPA cambió sus fuentes» once per state of SIAPA's files and of the repo's match with them; its last step enables both scheduled workflows again through the API, since GitHub disables a public repo's schedules after 60 days without activity. CI never commits the baseline: after reviewing a change, run `python3 pipelines/siapa_watch.py --update` and commit `siapa_sources.json`. SIAPA's CloudFront caches each file up to a day; query strings and no-cache headers don't bypass it.
- `siapa_mapa.py` writes `web/colonias_siapa.topo.json` and its `api/data` copy from the TopoJSON and `ajustes.php` behind SIAPA's map, with `l` on the colonias whose zones SIAPA's PDF list gives differently; it warns when `ajustes.php`'s days differ from `rotation.json` and doesn't apply its hand-made colonia changes yet (none so far). Then `mapa_colonias.py` writes `colonias_mapa.json` and the zones of `otras_colonias.json`.
- `colonias_poligonos.py` writes `pipelines/colonias.geojson` (INE outlines of SIAPA's colonias; no page loads it) and the names of `otras_colonias.json`.
- `promesas.py` and `publicaciones.py` build and check /promesas and `web/publicaciones.json` (see below). CI runs the `--check` of these two and of `mapa_colonias.py`.
- `secciones_ine.csv`: INE electoral section → Jalisco local district (4,080 sections; shared by Tachis Villalba, credited on /escribe; identical to INE's catalogue for entidad 14 on cartografia.ine.mx, cutoff 19 Jan 2026, checked 15 Oct 2026). `secciones_escribe.py` rewrites the `SECCIONES` string in `web/escribe.html` from it.
- `siapa_colonias.py` (needs pdfplumber, see README), `siapa_zonas.py`, `zonas_preview.py` (draws `experiments/landing/zonas.svg`) and `mymaps_kml.py` serve the older sources.

### `web/`: aguagdl.com, plain HTML with no framework

- **Hosting.** Cloudflare Pages deploys `web/` on every push to `main` (output directory `web`). Its build command must be `python3 pipelines/publicaciones.py --check && python3 pipelines/promesas.py --check && python3 pipelines/mapa_colonias.py --check`, so a broken data file stops the deploy instead of reaching the live map. Pages serves `privacidad.html` at `/privacidad`. Unknown paths get an empty 404 (checked 22 Oct 2026): the project serves neither `index.html` nor `404.html` for them, unlike classic Pages, so `404.html` (`noindex`) only shows at /404 until Cloudflare's not-found handling is set to serve it. `www.aguagdl.com` 301-redirects to the apex through a Cloudflare Redirect Rule (proxied AAAA `www` → `100::`), not through Pages, so don't add `www` as a Pages custom domain. Cloudflare Web Analytics is enabled from the Pages project's Metrics tab; Cloudflare injects its script and point 7 of the privacy notice describes it. Everything in `web/` is public: keep notes, unused data and drafts out of it.
- **Every page** loads `/theme.js` in its `<head>`: the light/dark button. Light is the default, and a page's `prefers-color-scheme: dark` rules apply only after a visitor picks dark, so style dark mode only with those media queries and use `aguaDark()` instead of `matchMedia` in scripts; a switch fires a `tema` event on `document`, on which the maps recolour. Each page has one `<meta name="theme-color" content="#ffffff">`, without `media` (theme.js changes it). The icon sprite is referenced as `/icons.svg?v=N#name` and cached for a day, so bump `v` in every page when you change `icons.svg`. Keep the `facebook-domain-verification` meta tag, which keeps aguagdl.com verified in Meta. The pages that call the API (`index`, `reportes`, `mapa`, `mizona`) use `https://api.aguagdl.com`, and `?api=http://localhost:PORT` points them at a local one (only localhost or 127.0.0.1 is accepted).
- **`_headers`**: HSTS, nosniff, referrer and permissions policies (`/mizona` needs `geolocation=(self)`), framing only by aguagdl.com itself (`frame-ancestors 'self'`, `X-Frame-Options: SAMEORIGIN`), and a CSP that allows only what the pages use: the API, OSM tiles, the players /noticias opens and Cloudflare's analytics beacon. Caching: SVG, PNG, `/img/*` and `/fuentes/*` for a day, `/vendor/*` for a year, immutable (a new Leaflet goes in a new folder), `/calendario/*` for an hour, and `promesas.json`, `publicaciones.json` and `colonias_siapa.topo.json` for 5 minutes; everything else revalidates on each visit.
- **`_redirects`**: /llego → /mizona, /palestina → /antisionismo and every old landing variant (/v1…/v15, and /v1/…/v5/, where the first ones lived) → /, all 301; and `/reportes-portada`, a rewrite (200) of /reportes for the landing's frame.
- **The menu** has eight entries: «¿Hay agua?» (/reportes), «Exige» (/exige), «Mi zona», «Noticias», «Congreso» (/escribe), «Cuentas» (/promesas), «Contaminación» and «Antisionismo». They wrap into two rows of four at 760 px or less, and below 980 px the icons hide. /avisos is linked from /reportes, /noticias and the footers of /reportes, /mapa and /escribe; /pipas from the landing, /reportes, /noticias and the bot.
- `index.html`, the landing, in a newspaper style. Under the kicker «El agua es un derecho. Exígelo.» and the headline, /reportes itself fills a frame edge to edge (88 % of the window's height, 80 % on phones), as /reportes shows it: the whole city, its summary and its timeline, which waits on the first day until most of the frame is on screen and then plays once; three seconds after landing the page scrolls down to the frame unless the visitor has scrolled, touched anything or asked for less motion; then SIAPA's promises beside the CEA's own counts, «¿Y en tu colonia?», «Lo que se publica», the /exige and vote-no boxes and the Congreso section. Quotes appear as written, each linked; private people appear by colonia and date only, never by name; Nothing on it is about the rotation's schedule, zones or reminders: those live on /mizona, /mapa and /avisos.
  - The frame loads `/reportes-portada` (`noindex`), so Web Analytics doesn't count the landing's visits as visits to /reportes. Framed, /reportes shows only its map from the first paint (the `en-portada` class), opens its links in the whole window and posts `mapa-listo` to the landing once its map is drawn or has failed; the landing shows the frame then (its `load` event is the fallback) and passes its theme on. One finger on a touch screen and a plain wheel scroll the landing; two fingers, Ctrl/⌘ + wheel or a trackpad pinch move and zoom the map, and a hint says so.
- `reportes.html` (/reportes): a full-screen map under the header, then the list of colonias, the week, the bot's answers by zone and «Cómo funciona». Since 22 Oct 2026 it is the former variant r1 «La crisis día por día»: a timeline under the map (play, a stacked chart by day that doubles as the scrubber, `?dia=YYYY-MM-DD` opens a date; hidden in the landing's frame) lights colonias up on their first publication, and each colonia's badge counts its reports up to that day and grows with them (smaller badges on top so all stay clickable). The summary at the top right gives the colonias with a week or more, the municipio shares and the four colonias with the most reports, all following the timeline's day. It draws from the static files without waiting for the API: `/v1/reportes` is applied when it arrives, and the refresh every 2 minutes replaces only the open card's counts. A colonia in the link opens without animation, and the street tiles load once, at its view.
  - A colonia with publications takes the colour of the most days they give (one red ramp: 1–2, 3–6, 7–13, 14 or more; dashed when none gives days; dark mode inverts it); one without them, the majority of the last 24 hours' reports. Sources count once per account, page or group (each comment is its own). Eco is shown but never treated as proof (false news spread further on Twitter, Vosoughi et al. 2018).
  - A colonia's card shows its sources' images, the posts (news first), the map's own 24-hour reports and the report form; after a report, its link to share and /exige. The map frames the colonia with one tile per publication, kept clear of the card and the controls. A browser keeps its own report of a colonia for an hour in `localStorage`, so the card thanks instead of asking again. If `publicaciones.json` doesn't load, the page says so.
  - `?q=&m=&cp=` opens a colonia; a bare `?q=` opens one only when one matches and lists them otherwise; `&reportar=1` opens the form.
- `exige.html` (/exige) builds a message from the colonia, the municipio and what happens, with SIAPA's own promise and article 4's words on the right to water, and gives each office a card: email (the visitor's mail app or Gmail), an X post and Facebook. Each contact comes from an official page (checked 20 Oct 2026), named on its card. SIAPA shows only for Guadalajara, Zapopan, Tlaquepaque and Tonalá; Tlaquepaque publishes no presidencia email, so it gets its accounts only; Zapotlanejo, Ixtlahuacán and Juanacatlán have no contacts yet; never use the old directors' or the previous Tlaquepaque mayor's addresses that stale official directories still list. Nothing is sent to Agua GDL.
- `pipas.html` (/pipas) gives SIAPATEL and each municipio's own line, each with its official source or the news report that quotes the announcement, the Ley del Agua's article 90, fracción VI, and the date they were checked. Publish a channel only when a source states it (SIAPABOT is SIAPA's line «para dudas», not a pipa channel; 073, not 070), and say a pipa is free only where the source does.
- `mizona.html` finds the zone by location or colonia and offers Telegram (`/start zN`) and the zone's calendar; on tap it loads `mapa.js` and shows SIAPA's map, and a tap on a spot with no colonia asks `/v1/zone`. `mapa.html` (/mapa) shows every colonia filled by zone, with search by name, municipio or postal code; the days come from `/v1/zones`, never from the map file, and fill in when they arrive.
- `mapa.js` holds the map code /mapa, /mizona and /reportes share (TopoJSON decoding, zone colours, drawing, highlights, and the wording helpers `zones`, `label` and `describe`). Leaflet is self-hosted in `vendor/leaflet-1.9.4/`, with OSM tiles (allowed in `_headers`, named in the privacy notice). `p` in the data is each multi-zone colonia's share of area per zone; below `BORDER` (15 %) the pages say the colonia is in one zone «al límite con» the other instead of in both, since most of SIAPA's two-zone colonias only graze a border.
- `avisos.html` is the subscribe page (Telegram `t.me/AvisoAguaGDLbot`, or the zone's calendar). `noticias.html` is the crisis day by day, curated by hand: videos load from YouTube, TikTok or X only when tapped (their thumbnails are in `img/videos/`, so opening the page contacts nobody), and «Día por día» filters by each `<article>`'s `data-tags`. Every item links its source; update «Última actualización» when you edit it.
- `promesas.html` (/promesas): each government water promise beside the law or document, with a verdict and steps. Its cards and meter are generated: edit `web/promesas.json`, then run `python3 pipelines/promesas.py`. It fails unless every source has an archive.org snapshot or a private copy (`"captura": "privada"`), «Incumplida» has two independent sources, «Se contradice» quotes the document, each entry has one core step, no «miente/engañó» appears outside quotes, and «israelí» appears only in a quote; `--check` fails if the page is stale; `--drafts --out DIR` previews without archives outside `web/`. The plan, research and private copies are in the private notes repo (`projects/promesometro.md`).
- `publicaciones.json` (checked by `pipelines/publicaciones.py`): news and neighbours' posts since 12 Oct 2026 about colonias without water, each with its link, date, colonias (keys of `colonias_mapa.json`), its words as published (`cita`, checked against the post when added), the days without water it gives (`dias`, or null), `bloqueo` for street blockades, and its reactions, comments and shares with the date they were read (`eco`).
  - News outlets (`fuente: medio`) count without a threshold and go first; neighbours (`vecinos`) need `regla.reacciones` reactions and `regla.comentarios` comments, and a neighbour's comment (`tipo: comentario`) counts only inside a post that meets the rule (`en`). One article can give several entries, one per quote; a story that retells a post names it in `de` and counts as that post's source.
  - Never a private person's name: `quien` is the outlet, «Grupo «…»» (public groups only) or «Cuenta de vecinos …»; `en.quien` (the post a comment is in) is an outlet some `medio` entry names, one of those, or a public page listed in `PAGINAS` in the script (add one only after checking it's a page, not a person). A link can still show an X handle; the privacy notice says anyone can ask soporte@aguagdl.com to remove theirs.
  - `--eco` refreshes the X numbers through X's public embed endpoint (`cdn.syndication.twimg.com`, no login); Facebook's need a login and keep the date they were read. `--imagenes` (macOS, `sips`) saves each post's preview as a 480 px JPEG in `web/fuentes/` (`vista`; null for a logo or stock picture, which keeps it out of later runs), so visitors never load Facebook, X or the outlets; `--capturas` (headless Chrome) saves the top of each news article as `web/fuentes/<hash>-t.jpg` (`captura`) and its `og:title` as `titular`. The private notes say how the posts were found.
- Advocacy pages: `escribe.html` (write to the 38 deputies), `contamina.html` (Río Santiago polluters) and `antisionismo.html` (the maintainer's position against the State of Israel). Every factual claim there links its source; keep it that way, and never state that an Israeli company is part of the Jalisco aqueduct APP unless a source shows it.
- `privacidad.html` and `terminos.html` are the privacy notice and terms of use; Meta's app settings link to them, so keep their URLs.
- Removed until there are enough reports, in git history: `resultados.html` (with `GET /v1/results`, `store.Results` and its menu and footer links) and `informes.html` (see `cmd/informe`).
- `experiments/landing/` (not deployed) keeps earlier landings and variants. `variantes.py` writes variants into `web/` from the blocks of `index.html`'s `<main>`, found by their class, so keep those classes; as it stands it rewrites the dropped fourth round (/v11…/v15), so change it before running it.
- Variants of /reportes (since 22 Oct 2026, noindex, each a standalone copy of `reportes.html` with a bar to switch between them and /reportes; the second round, the same day, keeps the map front and centre and tries other summaries): r1 «La crisis día por día» became /reportes itself on 22 Oct 2026 (/r1 301s there), `r2.html` «Zonas» (a tile per SIAPA zone with its colonias, most days and cut days; colour by days or by zone), `r3.html` «Quién lo dice» (colonias by evidence: reported by an outlet, several neighbours, one or two voices; filter by tier, municipio or outlet), `r4.html` «Lo nuevo» (new, ongoing and quiet colonias by their latest publication, a feed of the newest, «desde tu última visita» in localStorage), `r5.html` «Lo que ves» (the summary follows the visible map; 1 and 2 km rings around the visitor or anywhere, the location never stored or sent), `r6.html` «Burbujas» (a circle per colonia sized by its reports, a scoreboard band), `r7.html` «Calor» (a density glow that hands over to the colonias when zoomed in, a left rail), `r8.html` «Hexágonos» (1–3 km hexagons with the share of colonias with publications, a bottom sheet with tabs) and `r9.html` «Agujas» (a spike per colonia as tall as its days, rotating facts). They don't follow later changes to `reportes.html`; once the rest are dropped, 301 /r2…/r9 to /reportes too. SIAPA's map gives no zone to 1,533 colonias and puts only 9–11 in zones 1 and 7, so zone shares there rest on few colonias.

## Rules

- Never send real WhatsApp or Telegram messages from tests or local runs. `REMINDERS_ENABLED` and `TG_REMINDERS_ENABLED` stay false unless the maintainer turns them on in production.
- Channels: `subscriber.channel` is `wa` or `tg` (one subscription per channel and user ID); `reminder` and `notice` rows carry the channel too. Meta's caps and `NightCap` count WhatsApp only. The runner sends each enabled channel independently. A Telegram 403 (bot blocked) deletes the subscription and marks the attempt `blocked`; a 429 is waited out (nothing was sent).
- Don't relax the safety rails: idempotent sends per (subscriber, cut date), daily and monthly caps, the heartbeat, never resending an attempt WhatsApp may have accepted (only `rejected` attempts are retried), and the webhook signature check. A duplicate or missed reminder is the worst bug here.
- Caps: `DAILY_CAP` counts distinct recipients in a moving 24 hours, like Meta's messaging limit (250 for a new portfolio), across reminders and notices; when it's full the runner waits for the window instead of skipping anyone, and gives up only at `CATCH_UP_UNTIL_HOUR`. The bot refuses a subscription or zone change that would push any night over `DAILY_CAP` (`msgFull`). Raise `DAILY_CAP` only after Meta raises the portfolio's limit. `MONTHLY_CAP` counts messages (cost). Every WhatsApp reservation (nightly run, `notify`, `-tomorrow`) re-checks both caps under one Postgres advisory lock (`store.Budget`), so concurrent senders can't overshoot them; the admission check holds its own lock (`ZoneCounts`) through the subscription. Reports: only a subscription that already existed when a cut began can report that cut, so BAJA and subscribing again can't add reports. From the day after the rotation's `end` (`rotation.Over`) the bot refuses new subscriptions and zone changes, and its welcome says the rotation is over (BAJA still works).
- Privacy: store only the phone number, zone and consent time. BAJA must delete the subscriber; reports stay anonymous. Reports from /reportes never carry an IP, a location or a subscriber. A phone number belongs to at most one subscription, the one Meta most recently tied to it (partial unique index, migration 005): `Subscribe` and `ChangeUser` drop any other row holding it, and BAJA deletes every row with the sender's ID or number. Thirty days after `end` in `rotation.json` the server deletes every subscriber (`rotation.Expired`), as the privacy notice promises: move `end` if SIAPA extends the rotation. Never log phone numbers or WhatsApp message IDs: a wamid embeds the phone number, so the database stores only its SHA-256. No secrets in the repo; config comes from env vars (see `.env.example`).
- Public API protections: `/v1/*` allows 120 requests per minute per client IP (`Fly-Client-IP`, set by Fly's proxy; api.aguagdl.com is DNS-only, not behind Cloudflare's proxy) and, past 10,000 addresses in a minute, 1,200 shared among the new ones. Neon suspends after 5 idle minutes, so anything a stranger can trigger every few minutes would keep it awake and burn its free compute hours: public endpoints serve from memory, and what they read from Postgres is refreshed at most every 15–30 minutes. `/v1/zone` is `no-store` because it carries coordinates. Keep all of this when you add endpoints.
- WhatsApp templates are approved by Meta. If you change the parameters or buttons the code sends, the template in WhatsApp Manager must change too.
- Tests give the code a fixed `Now` inside the rotation, never the wall clock: with the real `rotation.json`, a test that reads the clock breaks when the rotation ends, and the weekly CI run goes red with no change.
- Keep code comments sparse and match the surrounding style. User-facing copy in plain Mexican Spanish. Commit messages in English, with a subject of at most 72 characters and the details in the body.
- Don't force-push. The maintainer may be editing in parallel: check `git status` before you edit or commit.
